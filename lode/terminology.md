# Terminology

- **Agent Skill** — a folder containing `SKILL.md` plus optional resources, loaded by a host when relevant.
- **SKILL.md** — the required entry file: YAML frontmatter plus instructions.
- **Canonical tree** — `.agents/skills`, the only real copy of every skill in this repository; it is not a required install location.
- **Skill group** — skills that share behavior under group-named central files, mirrored into each member and never linked to at runtime.
- **Group shared file** — the copy-ready `<group>-shared.md` central file; every member carries a byte-identical `references/<group>-shared.md`.
- **Repo-maintenance skill** — a skill that checks or changes this repository; it may name repo paths it checks, but still links only inside its own folder.
- **Progressive disclosure** — loading `name` and `description` at startup, the `SKILL.md` body on activation, and `references/`, `scripts/`, or `assets/` files only when the body names them.
- **Reference file** — a focused document under `references/` holding detail too dense for the body; named by `SKILL.md`, one level deep.
- **Skill size pass line** — the official recommendation for a `SKILL.md` body: under 500 lines and ~5,000 tokens; the catalog's ~200–300 line / ~3,000-token aim is advisory only.
- **Install copy** — one skill folder copied into a host's skills directory; it must work with no other file from this repository present.
- **Skill identity** — the folder name plus the `SKILL.md` inside it; the directory a host installs it into is never part of its identity.
- **Host** — an assistant or agent product that reads skills from disk.
- **Agent link** — a relative symlink to `../.agents/skills` placed where a host looks.
- **Wiring** — creating those links for a chosen set of hosts.
- **Default wiring** — `claude` plus `copilot`, the hosts that cannot rely on `.agents/skills`.
- **Opt-in host directory** — a native host directory created only when named or when `--all` is used.
- **Frontmatter** — the YAML block at the top of `SKILL.md`.
- **Description** — the frontmatter field hosts read before deciding to load a skill.
- **skills-ref** — the official reference validator from the Agent Skills project; it checks frontmatter and naming only.
- **Repo gate** — a skill that enforces this repository's catalog rules on top of the official validator; `skill-verify` is the only one.
- **AGENTS.md** — repository-agnostic agent instructions: how to work, git and privacy rules, verification, and documentation surfaces; it carries no project details.
- **Project guidance** — the repository-specific rules kept in `lode/`: layout, invariants, skills, scripts, commands, and validation.
- **README** — `README.md`, the high-level entry point for a repository visitor: what it is, what it contains, where to start.
- **Docs** — `docs/`, the human documentation tree, grouped by audience.
- **Docs audience** — one of `users/`, `operators/`, `developers/`, or `skills/` under `docs/`; each owns its detail, and other pages link to it.
- **Lode** — `lode/`, this agent-owned memory and the home of project-specific guidance.
- **Protected account** — an X account that hides its posts until it approves a follow request.
- **Moot** — a person the user follows who follows back; a `twitter-moot-radar` source and one `twitter-compatibility` scope.
- **Associated account** — a moot, a following-only account, or a followers-only account; the population `twitter-compatibility` scores.
- **Compatibility scope** — `moots`, `following-only`, `followers-only`, or `all`, chosen up front; it filters the population without changing the score formula.
- **Following-only** — an associated account the user follows that does not follow back.
- **Followers-only** — an associated account that follows the user without a follow back.
- **Category** — the per-target relationship label — `moot`, `following-only`, or `followers-only` — shown with a score but never scored itself.
- **Multimodal evidence** — opt-in reading of images, video frames, and audio transcripts; text is the default, 0 subject points when off, lower-weight and capped when on, and never enough for high confidence alone.
- **Evidence mode** — `text` (default, always on), `images`, `video`, or `audio`; each extra mode is opted in by the user and capability-tested once per run.
- **Evidence gate** — the two checks before non-text evidence counts: the user opted into that mode, and it passed its capability test this run; a failed gate is reported `unavailable`, never a silent zero.
- **Capability test** — the per-mode proof that the host returns readable pixels or a transcript; failure marks that mode `unavailable`, keeps the run text-only, and is reported instead of a silent zero.
- **Visual area** — an interest area whose primary evidence may be images; image or frame matches count 2 and cap at 12 instead of 1 and 6.
- **Evidence unavailable** — the per-mode flag when the model or browser tool cannot return readable content for an opted-in mode; the run continues text-only.
- **Overlap** — the count of distinct moots following a candidate; it ranks a suggestion, never proves an interest.
- **Interest profile** — the user's named areas plus strictness, overlap bar, and exclusions; it gates and ranks suggestions.
- **Compatibility score** — a 0–100 weighted total over a bounded sample of two feeds under one frozen rubric; arithmetic on counted items, never a prediction.
- **Rubric** — the user's areas, signal terms, area weights, component weights, mode, and window; frozen per version, and a change makes earlier scores stale.
- **Signal lexicon** — the confirmed lowercase terms per area that mark a match; the compatibility score's measuring instrument.
- **Component score** — one of subject, conversation, format, voice, recency, or access, each a count-based 0–100 value.
- **Confidence** — `high`, `medium`, `low`, `insufficient`, or `unreadable`, derived from the items and tabs read; shown beside a score, never folded into it.
- **Source feed** — the signed-in user's own readable Posts, Replies, Media, and visible Likes, re-read every run.
- **Target feed** — the scored account's public Posts, Replies, Media, and visible reposts for the scoring window.
- **Bridge matrix** — the report table of interest areas by the top-scoring accounts.
- **Entry point** — the newest matching post within 14 days that asks a question or invites a reply, with a suggested angle; never a sent message.
- **Stale score** — a score older than 14 days or from a different rubric version; shown only as previous, never ranked.
- **Source set** — the moots whose Following lists surfaced a candidate; it grows during a harvest and is reused across interest changes.
- **Proof standard** — a quoted post or bio line with date and permalink, the moots behind it, and a live `Follow` control reading; no suggestion without it.
- **Near miss** — a high-overlap candidate without readable interest evidence, listed separately so the user can overrule the rubric.
- **Pending** — the control state after requesting to follow a protected account; a request, not a follow.
- **Settle window** — the period after a click before judging whether the UI changed: checkpoints through roughly 30 seconds, then re-reads near 60 and 120 seconds, because a flip can land near two minutes.
- **Unreadable** — a page that rendered a notice instead of a profile, such as a sensitive-content interstitial; recorded as a verdict with a reason, never inferred from.
- **Follow-up pass** — the start-of-run check of due pending requests and unverified clicks.
- **Run state file** — per-account local JSON at `~/.x-<skill>/` holding the criteria or interests in force, cursor, queue, verdicts, and follow-ups; it persists between runs and is the only place a real handle or private detail is written. When writing is refused or unavailable, the same structure is held in session state and printed for the user to verify, and the next run starts fresh.
- **State line** — the one- or two-line start-of-run summary of the state file path and what it currently holds; with no file, it names the path and says the run starts fresh, or session-only when writing is unavailable.
- **Persistence fallback** — continuing a state-writing run on in-memory session state when file write is refused or unavailable, printing it for the user to verify, and accepting that the next run starts fresh and may repeat work.
- **Linked evidence** — a handle, quote, or date in a run's output that opens the X profile or post it came from; only pages read in that run are linked, never a guessed URL.
- **Access failure** — a browser, network, or site condition that stops a page or control from rendering; a run-level stop and flag, never a verdict about the account.
- **Placeholder handle** — a fictional handle such as `@alice` used in skill text, docs, and examples; real handles exist only in the run state file or in session state printed for the user to verify.
- **Human cadence** — jittered waits, scroll steps, pointer moves, and dwell times drawn from ranges so a run does not read as a fixed click rhythm.
- **X core contract** — [`docs/skills/twitter-core.md`](../docs/skills/twitter-core.md), the authoring home for rules shared by every browser-driven X skill; skill bodies mirror it and never link to it.
